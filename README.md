# Threshold Password Authentication Protocols

Research implementations and benchmark tools for UpSPA, RoUpSPA, PAS-TA-U, and
AugSSO. The repository includes protocol state machines, independent-process
network experiments, fault and recovery tests, and reproducibility scripts.

Build requirements and execution commands appear below. Validation results are
recorded in [docs/validation/README.md](docs/validation/README.md), and the
artifact layout is described in [docs/ARTIFACT_STRUCTURE.md](docs/ARTIFACT_STRUCTURE.md).
The source archive digests are listed in [SOURCE_ARCHIVES.txt](SOURCE_ARCHIVES.txt);
[SOURCE_SHA256.json](SOURCE_SHA256.json) records the current source file hashes.

The benchmark transport is research TCP. Protocol assumptions and unresolved
recovery boundaries are documented in [PROTOCOL_GAPS.md](PROTOCOL_GAPS.md) and
[REVISION_NOTES.md](REVISION_NOTES.md).

For **all 15 RoUpSPA experiments plus both PDF comparison groups**, use
[RUN_ALL_MEASUREMENTS.md](RUN_ALL_MEASUREMENTS.md):

```bash
bash run_measurements.sh start
```

This unattended command covers the exact PDF grids. The earlier focused runner
is documented in [RUN_NEW_RESULTS.md](RUN_NEW_RESULTS.md); its `paper-minor`
selection is not the complete plan. The original modeled comparisons and the
revised process/network measurements retain separate interpretation labels.

The new `bench_network` runs the existing RoUpSPA state machines and the modern
PASTA-U/AugSSO cryptography across independently launched processes. A client,
each provider, and each verifier run in separate Linux namespaces. The Rust
harness configures veth links, a private bridge, routes and `tc netem`, records
observed RTT, runs services, saves results, and removes only resources it created.
The original local and modeled experiments remain below under their old labels.

The protocol reference is `RoUpSPA_Updatable__DiSPP__Fault_Tolerant___Journal_.zip`
(`sections/3_Model.tex` and `sections/4_Protocol.tex`); the network reference is
`UpSPA___WPES_version (10).zip` (`ACNS/sections/8-implementation.tex`).
`SOURCE_ARCHIVES.txt` records these exact inputs and the primary `crates.zip`
SHA-256 hashes. The network adapter implements the restricted recovery rules
and new-password consistency checks described in the revision notes.

Start with [BASELINE.md](BASELINE.md), [PROTOCOL_GAPS.md](PROTOCOL_GAPS.md),
[BASELINE_NETWORK.md](BASELINE_NETWORK.md), and
[IMPLEMENTATION_REVIEW.md](IMPLEMENTATION_REVIEW.md). Two manuscript gaps are
reproduced by tests: an undetected stale threshold can authenticate the old
password, and signed account writes do not establish login-server Store.
The revised adapter uses r = n_sp - q_sp + t_sp reads and leaves unsafe
account recovery and unsupported identification advancement unresolved. Signed
records alone do not establish completion; no completion certificate is invented. The transport is research
TCP on an isolated host and does not implement the manuscript's confidential,
authenticated channel assumption. This is a runnable benchmark, with those
protocol/security limitations explicitly preserved.

## Build and verify

Use the pinned Rust 1.93.0 toolchain. The language floor is 1.82. Linux needs
`iproute2`, `iputils-ping`, a C linker/compiler, OpenSSL development libraries
for the preserved SSH benchmark, and permission to create namespaces/configure
links and qdiscs (usually root).

```sh
cargo build --locked --release --workspace --all-targets
cargo test --locked --workspace --all-targets
target/release/bench_network check
target/release/bench_network capabilities
target/release/bench_network validate --config config/network-smoke.json
sudo target/release/bench_network smoke --config config/network-smoke.json
```

Windows builds and socket correctness tests can exclude the legacy SSH crate
when native OpenSSL is absent:

```sh
cargo test --locked --workspace --exclude pastau_paper --all-targets
cargo build --locked --bin bench_network
target/debug/bench_network local-smoke --config config/network-smoke.json
```

`local-smoke` and `local-fault` use independently launched processes on loopback
and apply no network impairment. They are not namespace timing experiments.

## Configuration and operations

Small smoke configurations are included under `config/`; the reproducible paper
matrices are generated by `scripts/paper_configs.py`. Use `paper-minor` for the
focused revision or copy a smoke configuration for a manual trial.
`n_sp`, `t_sp`, and `q_sp` must satisfy
`1 <= t_sp <= q_sp <= n_sp` and `2*q_sp - n_sp > t_sp - 1`. Synchronization needs
`q_sp` **other** responses; `q_sp=n_sp` cannot meet this boundary. The
non-verifiable new-password consistency check additionally requires
`read_size >= 2*t_sp - 1`; otherwise Password Update cleanly aborts before writes. Select `phase`
and `schemes`; Secret Update and synchronization accept only RoUpSPA.

Profiles take a name, per-direction `delay_ms`, `jitter_ms`,
`bandwidth_mbps`, and `loss_percent`. Client and service egress each receive
the same qdisc; nominal RTT is twice `delay_ms`, and measured ping output is
authoritative. Extra `loss_levels` combine with each profile loss as
`1-(1-profile_loss)*(1-extra_loss)`, where losses are fractions. Warm-ups,
samples, repetitions, `delta_ms`, `retry_ms`, and `timeout_ms` are configurable.
Namespaces replace the template's loopback addresses; the requested and resolved
configurations are saved. `state_dir` is placed beneath each run's output when
relative, or beneath its own unique run directory when absolute.

```sh
sudo target/release/bench_network compare --config config/network-registration-smoke.json
sudo target/release/bench_network compare --config config/network-password-smoke.json
sudo target/release/bench_network compare --config config/network-secret-smoke.json
sudo target/release/bench_network compare --config config/network-loss-smoke.json
sudo target/release/bench_network fault --config config/network-terminal-fault-smoke.json
sudo target/release/bench_network fault --config config/network-client-restart-smoke.json
sudo target/release/bench_network fault --config config/network-provider-restart-smoke.json
sudo target/release/bench_network compare --config config/network-sync-smoke.json
target/release/bench_network summarize --input RUN/raw.jsonl --output RUN/summary.json
```

Fault runs support whole-message suppression, endpoint crashes before/after a
handler's durable transition, and endpoint stop/restart. Client faults use
`crash_before` or `crash_after` at `ls_prepare`, `provider_write`, or `terminal`,
then launch a new client process to resume its exact persisted transaction.
Endpoint fault modes are armed after fixture setup by a controlled quiescent
relaunch. This injection-only relaunch retains active replicas; a genuine restart
without the fault variables marks known families stale. The separate process regression also suppresses a live provider's whole
Password Update without a restart, reproducing the undetected-miss gap.
Account synchronization after a restart is intentionally unresolved where
completion evidence is unavailable. Identification recovery remains provider
initiated and never copies another provider's TOPRF share.

For manual deployments, `service --config FILE --scheme SCHEME --role provider
--id ID --listen ADDRESS --state DIRECTORY` starts a provider; use role `login`
and id `0` for the verifier. Baselines need `provision --scheme SCHEME --config
FILE --state ROOT` once, outside timing; then launch each role from its own
directory. `client --scheme SCHEME --phase PHASE --config FILE --state CLIENT_DIR
--output RESULT.json` invokes one operation. RoUpSPA recovery phases are
`resume`, `discard`, and `retry_terminal`; controlled test staging also exposes
`*_prepare_only` and `*_write_once`. Registration and Secret Update allow only pre-write Discard. Password Update
also allows Discard of tentative provider writes before Store. The terminal
decision is persisted before transmission and survives client restart.
One process/writer per state directory is supported. Journals/snapshots contain
benchmark secrets and should be handled as private research data.

## State, completion and measurement

Durable role transitions flush before a request-response acknowledgement.
State snapshots replace the previous file atomically; Linux flushes both file
and parent directory, and Windows uses write-through replacement. Client logs
retain exact request bytes and acknowledged providers across interruption.
Registration and Secret Update run login Prepare, direct provider quorum writes,
then one-way login Store. Password Update uses existing TOPRF shares, tentative
quorum writes, and one-way provider Store, with no login-server interaction.
Authentication is read-only. Terminal rounds retransmit identical bytes during
Delta and wait a full Delta after the last send; this wait is in return latency.

All schemes use `fresh_per_request` TCP connections; connection establishment
is inside operation latency. This common policy differs from the historical
manuscript's connection reuse methodology and is saved explicitly. Every sample gets a fresh
durable fixture; provision/setup/bootstrap are excluded from the measured phase,
while protocol randomness, client journal flushes, crypto, transport, and final
completion waits are included. The operation timer starts inside the client at
invocation and ends after outstanding requests are drained. `quorum_ns` records
stage completion separately. `process_wall_ns` also includes client startup.

Traffic counts are actual framed application bytes written/read at sockets,
including JSON/frame metadata and observed partial transfers, not trace-size
estimates. They exclude TCP/IP headers, handshakes and kernel retransmissions;
`tc -s` snapshots retain additional kernel observations. Provider-initiated
synchronization traffic is recorded in `sync-transports.jsonl` and added once
to measured traffic. Handler time is observed endpoint wall time, including
durable storage; synchronization handlers also include their peer waits.
`client_ns` measures caller elapsed work with blocking stage/socket/terminal/drain
waits subtracted; it is not process CPU time. Parallel metrics are not additive
components of end-to-end time. `terminal_handler_ns` is distinct from the
terminal-send/Delta `terminal_ns` interval.

Raw JSONL preserves measured, warm-up, fixture, failed and recovery sessions.
Outcomes are `completed`, `cleanly_aborted`, `unresolved`, or `failed`, each with
a reason when needed. No formal acknowledgement is added to terminal messages.
The harness independently checks durable endpoint processing: a missing Store
outside the synchronous assumption is unresolved, and its own client log is
frozen for exact retry. Killed clients cannot report their own CPU/retry/prefix
telemetry; these rows explicitly set `client_measurement_unavailable` and use
observed endpoint traffic and external process elapsed time. These observations
may omit interrupted prefixes and are not presented as complete client telemetry.
The Rust summarizer includes unsuccessful attempts in denominators, reports p50
and p95, separates recovery phases, and writes `session-outcomes.json` including
all bootstrap/warm-up outcomes. Machine/kernel/Rust versions, binary digest,
connection/timing policy, actual network commands/qdiscs and RTT are saved per run.

See [NETWORK_VALIDATION.md](NETWORK_VALIDATION.md) for historical smoke commands
and results from the earlier source. They do not validate this revision. New
measurements and process regression tests must be run on the benchmark machine.

# Preserved local and modeled benchmarks

This repository provides one reproducible Rust benchmark for four password-authentication constructions used in the paper:

| CLI scheme | Implementation included | Main measured phases |
|---|---|---|
| `upspa` | latest UpSPA benchmark path, including lightweight password update v2 | setup, registration, authentication, secret update, password update |
| `pastau` | PAS-TA-U with Ristretto TOPRF and threshold BLS token generation | setup, registration, authentication, password update, verification primitives |
| `augsso` | registration-corrected AUGSSO with password update | setup, registration, authentication, password update |
| `upspa-quorum` | admissible ABD-style quorum variation of UpSPA | registration, secret update, password update |

`bench_unified` is the primary cross-protocol interface. It validates one parameter grid, applies the same timing and network settings to every selected scheme, runs the scheme engines sequentially, and writes one normalized whitespace-separated result file. Dedicated PAS-TA-U binaries under `src/bin/` and `pastau_paper/src/bin/` reproduce the three-way validation described below.

The code is intended for research benchmarking and protocol comparison. It is not a production authentication service.

## Quick start

Requirements:

- Rust 1.93.0 through `rust-toolchain.toml` (the crate language floor is 1.82)
- Cargo
- a native linker and C build toolchain

On Windows with the default MSVC Rust target, install Visual Studio Build Tools with **Desktop development with C++**. WSL with a Linux Rust toolchain is also supported.

Build the pinned dependency set:

```bash
cargo build --locked --release --bin bench_unified
```

Inspect a run without executing benchmarks:

```bash
cargo run --locked --release --bin bench_unified -- \
  --scheme all \
  --kind all \
  --nsp 20 \
  --tsp 12 \
  --dry-run
```

Run the paper configuration with explicit `NSP` and `TSP` values:

```bash
cargo run --locked --release --bin bench_unified -- \
  --scheme all \
  --kind all \
  --net all \
  --nsp NSP \
  --tsp TSP \
  --sample-size 200 \
  --warmup-iters 50 \
  --proc-warmup 200 \
  --proc-samples 1000 \
  --lan-rtt-ms 0.5 \
  --lan-jitter-ms 0.05 \
  --lan-bw-mbps 1000 \
  --wan-rtt-ms 60 \
  --wan-jitter-ms 5 \
  --wan-bw-mbps 50 \
  --overhead-bytes 64 \
  --offline max \
  --pwdupd v2 \
  --out results/paper_bench.dat
```

Replace `NSP` and `TSP` with positive integers satisfying `1 <= TSP <= NSP`. The quorum benchmark uses the maximum admissible number of offline providers by default; `--offline max` is shown explicitly so the experimental condition is visible in the command.

## Unified benchmark kinds

The baseline schemes (`upspa`, `pastau`, and `augsso`) support:

| Kind | Measurement |
|---|---|
| `proto` | measured client-side protocol computation |
| `prim` | measured cryptographic primitive microbenchmarks |
| `sp` | measured server/provider computation and in-memory storage operations |
| `net` | modeled network time with server processing set to zero |
| `full` | measured client computation plus modeled network time and calibrated server p50 processing |

The quorum scheme supports:

| Kind | Measurement |
|---|---|
| `full-no-net` | complete local quorum protocol with real cryptographic work and provider state transitions, without artificial network delay |
| `full-net` | the same local execution plus LAN or WAN message-level simulation |
| `quorum-overhead` | ABD synchronization overhead for quorum write and stale-provider recovery |

`--kind all` selects every applicable kind. If a selected kind does not apply to a selected scheme, that scheme is skipped for that kind. Quorum authentication is intentionally absent because the updated online authentication path is quorum-free.

## Parameter contract

All list values are comma-separated. The unified runner rejects unknown flags, empty lists, invalid thresholds, zero sample counts, invalid network values, and inadmissible explicit offline counts before starting a benchmark.

| Flag | Accepted values | Default | Scope |
|---|---|---|---|
| `--scheme` | `all`, `upspa`, `pastau`, `augsso`, `upspa-quorum`; comma lists allowed | `all` | scheme selection |
| `--kind` | `all`, `proto`, `prim`, `sp`, `net`, `full`, `full-no-net`, `full-net`, `quorum-overhead` | `all` | benchmark selection |
| `--ops` | `all` or a list of `reg`, `secupd`, `pwdupd` | `all` | quorum phases |
| `--nsp` | positive integer list | `20,40,60` | provider counts |
| `--tsp` | integer list with `1 <= tsp <= nsp` | unset | absolute thresholds |
| `--tsp-pct` | integer percentage list in `1..=100` | `60` | thresholds computed as `ceil(nsp * pct / 100)` |
| `--sample-size` | positive integer | `200` | timed observations per row |
| `--warmup-iters` | nonnegative integer | `50` | warmup observations per row |
| `--proc-warmup` | nonnegative integer | `200` | server p50 calibration warmup |
| `--proc-samples` | positive integer | `1000` | server p50 calibration samples |
| `--rng-in-timed` | switch | off | include applicable RNG work in timed client/server regions |
| `--net` | `lan`, `wan`, `all` | `all` | network profiles |
| `--lan-rtt-ms` | finite nonnegative number | `0.5` | LAN round-trip latency |
| `--lan-jitter-ms` | finite nonnegative number | `0.05` | LAN bounded jitter |
| `--lan-bw-mbps` | finite positive number | `1000` | LAN bandwidth |
| `--wan-rtt-ms` | finite nonnegative number | `60` | WAN round-trip latency |
| `--wan-jitter-ms` | finite nonnegative number | `5` | WAN bounded jitter |
| `--wan-bw-mbps` | finite positive number | `50` | WAN bandwidth |
| `--overhead-bytes` | nonnegative integer | `64` | framing overhead added to each message |
| `--offline` | `max`, `none`, or a nonnegative integer | `max` | quorum provider unavailability |
| `--pwdupd` | `v1`, `v2`, `both` | `v2` | UpSPA password-update variant |
| `--out` | file path | `results/unified_bench.dat` | unified output |
| `--dry-run` | switch | off | validate and print the resolved configuration only |

`--tsp` and `--tsp-pct` are mutually overriding: the last one on the command line selects the threshold mode. With multiple `nsp` and absolute `tsp` values, the benchmark evaluates their Cartesian product. Every absolute threshold must therefore be valid for every selected `nsp`. Use separate commands when the experiment requires paired rather than Cartesian configurations.

Compatibility aliases are accepted for `--samples`, `--warmup`, `--rng`, `--schemes`, and `--unavailable`.

## Quorum condition and offline providers

For quorum-based UpSPA, the storage-provider quorum is

```text
qsp = ceil((nsp + tsp) / 2)
```

The implementation enforces:

```text
1 <= tsp <= qsp <= nsp
2 * qsp - nsp > tsp - 1
```

The full phase needs both `qsp` available storage providers and `tsp` available TOPRF providers. Therefore:

```text
offline_max = nsp - qsp
```

For example, `nsp=20` and `tsp=11` produce `qsp=16`, so `--offline max` runs with four unavailable providers. An explicit count greater than four is rejected before execution.

Quorum writes update only the selected live quorum. A non-quorum provider can remain stale, and the recovery path reads a quorum and installs the freshest counter value. Password update uses the updated lightweight construction: TOPRF under the old and new password with unchanged provider shares, re-encryption of `cipherid`, one signature, and a quorum write of the signed master record.

## Network model

The network simulator operates at the message level. Each transfer includes:

- one-way propagation time equal to `RTT / 2`;
- deterministic pseudorandom bounded jitter;
- serialization time derived from payload bytes, framing overhead, and configured bandwidth;
- protocol-specific fan-out/fan-in and round structure;
- provider processing p50 only for `full` rows.

`net` rows contain no server processing. `full` rows are modeled totals, not wall-clock socket measurements. The quorum `full-net` path adds the same style of network model to a complete locally executed state transition.

## Determinism and timing

Protocol fixtures and simulated jitter use deterministic BLAKE3-derived ChaCha20 seeds. Identical parameters therefore generate identical protocol inputs and network random streams. Runtime measurements still vary with hardware, CPU frequency, operating-system scheduling, and background load.

RNG setup is outside the timed region by default where the source benchmark provides a precomputed path. Use `--rng-in-timed` only when the experiment explicitly includes randomness generation cost. That flag applies to the three baseline schemes; quorum rows report `rng_in_timed=0` because the quorum engine measures complete state transitions under its fixed timing definition.

For paper-quality measurements:

1. build and run with `--release` and `--locked`;
2. use the same host, power policy, CPU affinity, and network parameters for all compared runs;
3. stop unrelated workloads and avoid thermal throttling;
4. run at least three independent processes and report the aggregation rule used in the paper;
5. record CPU, operating system, Rust version, commit hash, and the complete command line.

## Output format

The output is UTF-8, whitespace-separated, one header followed by one row per operation:

```text
scheme kind op net_profile rng_in_timed nsp tsp qsp unavailable samples warmup min_ns p50_ns p95_ns max_ns mean_ns stddev_ns
```

| Column | Meaning |
|---|---|
| `scheme` | `upspa`, `pastau`, `augsso`, or `upspa_quorum` |
| `kind` | benchmark kind using underscore form in data rows |
| `op` | scheme-specific operation label |
| `net_profile` | `lan`, `wan`, or `none` |
| `rng_in_timed` | `1` when applicable RNG work is timed, otherwise `0` |
| `nsp`, `tsp` | provider count and threshold; parameter-independent primitive rows may use zero |
| `qsp` | quorum size, or zero for baseline schemes |
| `unavailable` | offline provider count, or zero for baseline schemes |
| `samples`, `warmup` | observations used for the row |
| `min_ns`, `p50_ns`, `p95_ns`, `max_ns` | order statistics in nanoseconds |
| `mean_ns`, `stddev_ns` | arithmetic mean and sample standard deviation in nanoseconds |

Operation labels are preserved from each validated scheme implementation so older paper scripts can map rows without losing phase detail. The separate `net_profile` column removes the need to infer LAN/WAN solely from the operation label.
